# 带话：让两个会话知道彼此的来路

## 它解决什么

QQ 渠道里每个联系人各有一个会话（甲是 `qq-dm-<甲>`，乙是 `qq-dm-<乙>`）。会话之间不共享上下文。
甲让 A 带话给乙，A 直接发出去，乙的回复却只会进 B；B 不知道甲托了什么，于是开始乱说。

插件用两条路补上这个洞：

1. **自动同步背景**：A 跨聊发出去的消息，插件在发送成功后把来路和原文注入对方会话（不唤醒）。
2. **`qq_relay` 显式交接**：A 把话交给 B，由 B 用自己的口吻发给乙。

## 自动同步（默认生效）

A 调 `qq_send_text({ isGroup, target, text })` 发给「不是当前聊天对象」的人，`tools/result` 成功后：

1. 由 `sessionId` 和工具参数推出「这次本该落在哪个房间」：群 → `qq-hub`；`vipIds` 里的号 → `qq-vip`；其余 → `qq-dm-<QQ>`。
2. 和 A 自己的房间相同就跳过（B 发给乙不会回头注入 B）。
3. 在会话列表里按 `updatedAt` 找该房间最新代（`-rN` 后缀）。
4. `resolveAgent` → `agent.inject(...)`，内容是：

```text
【带话 · 自动同步 · 来自「QQ 2174007116」】

「QQ 2174007116」那边刚才给 QQ 3599612346 发了一句话，原样是：
> 今晚不去了，你们玩

这句话已经直接发到 ta 的窗口了，你不用再发一遍；ta 之后回你时，
知道它是「QQ 2174007116」那边托人带过来的就行。
```

`inject` 只落盘进待处理队列，**不唤醒、不多花一次模型调用**；B 在乙回话的那一轮开头自然会看到。
按 `callId` 去重；目标会话还没建、或 `resolveAgent` 失败，只写日志，不抛错、不打扰任何人。

## `qq_relay` 显式交接

甲：「帮我跟他说：今晚不去了。」

A 调：

```json
{ "to": 12345678, "text": "今晚不去了", "from": "甲" }
```

插件找到 `qq-dm-12345678`（或它最新的 `-rN` 代际），把下面这段投进 B 的待处理上下文并唤醒它：

```
【带话 · 来自「甲」的会话】

甲 让我把这句话转告 QQ 12345678：
> 今晚不去了

这是转交的话，不是对方发来的。请用 qq_send_text 发给对方（isGroup: false, target: 12345678），文字就写「甲说，今晚不去了」。
发完不用回复甲。
```

B 这一轮如果自己发了，插件不管；整轮都没发，插件兜底用同一个工具代发。

## 为什么 `qq_relay` 还需要关键词

自动同步不需要模型配合；`qq_relay` 需要 A 主动选择它，所以加一道授权：甲的话里出现 `转告`、`帮我跟他说` 之类，
插件才记下「这个会话现在可以带话」，有效期默认十分钟。这样 A 不会因为自己的猜测把人拉进对话。

关键词只看甲对 A 说的话（`source.plugin` 为 `session-relay` 的合成消息会被跳过），
不看你写给乙的正文，也不会出现在乙看到的文字里。

## 边界

- 只处理 QQ 会话（`qq-*`）。
- 自动同步是单向、一次性的：乙的回复不会自动回到 A。
- 注入正文截断到 600 字；图片、文件、语音只留一句说明，不转附件。
- 目标会话不存在，或目标发不出去（QQ 渠道的发送闸门），工具会报错/日志留痕，不会静默吞掉。
