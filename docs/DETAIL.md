# 带话：把一句话交接给对的人

## 它解决什么

QQ 渠道里每个联系人各有一个会话（甲是 `qq-dm-<甲>`，乙是 `qq-dm-<乙>`）。会话之间不共享上下文。
甲让 A 带话给乙，A 直接发出去，乙的回复却只会进 B；B 不知道甲托了什么，于是开始乱说。

带话把这条路拆成两步：

1. A 不直接发给乙，而是把话交给 B（`qq_relay`）。
2. B 拿到前因，用自己的口吻发给乙。

乙看到的是「甲说，今晚不去了」；B 也从第一句话起就知道这是甲托的话。

## 使用

甲：「帮我跟他说：今晚不去了。」

A 调：

```json
{ "to": 12345678, "text": "今晚不去了", "from": "甲" }
```

插件找到 `qq-dm-12345678`（或它最新的 `-rN` 代际），把下面这段投进 B 的待处理上下文并唤醒它：

```
【带话 · 来自「甲」的会话】

甲 让我把这句话转告 QQ 12345678：
> 今晚不去了

这是转交的话，不是对方发来的。请用 qq_send_text 发给对方（isGroup: false, target: 12345678），文字就写「甲说，今晚不去了」。
发完不用回复甲。
```

B 这一轮如果自己发了，插件不管；整轮都没发，插件兜底用同一个工具代发。

## 为什么需要关键词

工具本身只管交接，不管「该不该交」。关键词是授权信号：甲的话里出现 `转告`、`帮我跟他说` 之类，
插件才记下「这个会话现在可以带话」，有效期默认十分钟。这样 A 不会因为自己的猜测把人拉进对话。

关键词只看甲对 A 说的话（`source.plugin` 为 `session-relay` 的合成消息会被跳过），
不看你写给乙的正文，也不会出现在乙看到的文字里。

## 边界

- 只处理 QQ 会话（`qq-*`）；别的会话里工具不出现。
- 一次性：乙的回复不会自动回到 A。
- 只交接文字；图片、文件、语音不转。
- 目标会话不存在，或目标发不出去（QQ 渠道的发送闸门），工具会报错/日志留痕，不会静默吞掉。
